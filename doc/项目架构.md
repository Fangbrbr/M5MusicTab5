# TAB5_MUSIC_PAD 项目架构与开发计划

> 本文档为 TAB5_MUSIC_PAD 的系统架构总览与阶段性开发计划。项目基于 ESP32-P4 (M5Stack TAB5)，使用 ESP-IDF v5.4.4 开发框架；核心使用 C，`engine_sf2`、`service_rtc` 因移植第三方库使用 C++ 并对外暴露 C 接口。
>
> 注意：音色方案统一为 SF2（SoundFont 2），由 engine_sf2 组件负责合成与采样回放。

---

## 1. 项目概览

### 1.1 产品定位

**TAB5 Music Box** 是一只面向全年龄的「音乐瑞士军刀」，并以一只可爱的**金丝熊（Hammy）**作为项目吉祥物贯穿所有视觉设计。

- 对**儿童/零基础者**：它是「声音玩具 + 乐理启蒙书」，有吉祥物陪伴，先玩后懂。
- 对**业余爱好者**：它是随身参考工具（五度圈、和弦、节拍、练耳、时钟）。
- 对**专业音乐人**：它是便携灵感速记本、MIDI 播放器和小型演奏终端。

核心卖点：

1. **App 化小工具**：每个 App 只解决一个小痛点。
2. **金丝熊主题视觉**：温暖、可爱、统一，区别于冷冰冰的音乐软件。
3. **MIDI 事件总线驱动**：UI 与 App 后端、App 与 App 之间全部通过 MIDI 事件通信。
4. **统一音频引擎**：SF2 引擎负责全部合成与采样回放，音色数据通过 SF2 音色加载。

### 1.2 当前进展

项目阶段性基础底层框架已搭建完成：

  - `engine_xxx`：算法/协议引擎

  - `task_xxx`：FreeRTOS 任务组件

## 3. 核心设计原则

| 原则 | 说明 |
|------|------|
| **不重复造轮子** | TAB5 BSP (`espressif__m5stack_tab5`) 已封装全部硬件驱动，Services 直接使用 BSP API，不再创建额外 Driver 抽象层 |
| **引擎独立** | Engines 是纯算法/协议层，零硬件依赖，可独立单元测试 |
| **配置归属模块** | 各模块的配置宏（`DMA_BUFFER_LEN`、`MAX_VOICES`、`MIDI_IN_DEV` 等）写在各自模块的头文件中，不设立全局 `config.h` |
| **事件总线统一** | 所有输入（MIDI/触摸/按钮）通过 `engine_midi` 事件总线分发，多生产者多消费者订阅制；输出覆盖内部引擎、BLE、串口、UI 显示等 |
| **App 生命周期管理** | `app_manager` 统一管理所有 App 的启动、挂起、恢复、杀死和资源回收 |
| **音频独占 Core1** | 音频渲染任务独占 Core 1，确保实时性；其他所有任务在 Core 0 |
| **前后端分离** | UI 前端由 EEZ Studio 可视化开发，后端为 IDF Engines/Services，通过 UserAction 回调通信 |
| **以 C 为主** | 核心模块使用 C；`engine_sf2`、`service_rtc` 因移植第三方库使用 C++，对外暴露纯 C 接口 |
| **5 点触摸映射** | 硬件支持 10 点电容触摸，但 ST7123 触摸 IC 不提供 track_id；项目当前在 `engine_gui` 中按 5 点进行坐标帧间跟踪，并为每个点注册独立 `lv_indev_t`，共享同一触摸 IC 数据缓存 |

## 4. 用户痛点与 App 抽象

### 4.1 儿童与零基础者

| 痛点 | App | 解决方式 |
|------|-----|----------|
| 乐理符号太抽象 | `app_zen` | 禅模式：小球碰壁反弹触发音阶，营造冥想式声音空间 |

### 4.2 业余爱好者

| 痛点 | App | 解决方式 |
|------|-----|----------|
| 调号/五度圈查起来麻烦 | `app_circle_of_fifths` | 交互式五度圈，一键看调号与和弦 |

| 想随手弹旋律找灵感 | `app_tiny_piano` | 多触点钢琴 |
| 想要自由演奏面板 | `app_xy_pad` | 横向音高、纵向音量，像特雷门琴 |

### 4.3 专业学习者 / 职业音乐人

| 痛点 | App | 解决方式 |
|------|-----|----------|
| 绝对/相对音感要碎片练 | `app_ear_trainer` | 随机出题、计分、难度递增 |

| 不插电播放 MIDI | `app_midi_player` | SD 卡 `.mid` + SF2 引擎音色播放 |
| 便携练耳/视唱 | `app_sight_singing` | 看谱唱/弹判断音准（后续扩展） |

## 8. 任务与调度

| 任务组件 | 优先级 | 核心 | 周期 | 职责 |
|:---|:---:|:---:|:---:|:---|
| `task_gui` | 5 | 0 | 10 ms | LVGL tick + 显示刷新 |
| `task_input` | 7 | 0 | 10 ms | 触摸/按键/MIDI 输入轮询 |
| `task_comm` | 4 | 0 | 10 ms | `engine_midi_process()` 事件分发 |
| `task_app` | 4 | 0 | 10 ms | 激活 App 的 `on_update()` 调度；分发 HTTP 完成回调 |
| `task_audio` | `configMAX_PRIORITIES - 1` | 1 | 无（死循环） | 音频渲染块处理，阻塞写 I2S |
| `task_network` | 3 | 0 | 事件驱动 | 执行 `service_http_client_process_one()`，集中处理阻塞 HTTP/HTTPS 请求 |

**约束**：Task 为纯胶水层，不包含业务逻辑；非必要不允许新增任务。`task_network` 是为隔离阻塞型网络 I/O 而新增的例外。

## 9. 各层详细说明

### 9.1 Engines 层（纯算法，零硬件依赖）

#### engine_midi — MIDI 事件总线（系统核心）
- **职责**：系统内部唯一的事件分发通道；支持 MIDI 1.0 全部通道消息与系统消息解析；通过 SysEx 承载项目内部控制指令
- **模式**：多生产者随时投流 + 多消费者按类型/通道订阅分发，线程安全
- **生产者**：UART MIDI、USB Host/Device MIDI、BLE MIDI、UI、MIDI 文件解析器等 service 模块通过 `engine_midi_feed_byte()` / `engine_midi_feed_stream()` / `engine_midi_publish()` 投流
- **消费者**：engine_sf2、各 App、BLE 输出、串口输出、UI 显示等通过 `engine_midi_subscribe()` 订阅
- **配置**：`components/engine_midi/include/engine_midi_config.h`
- **数据结构**（C）：
  ```c
  typedef enum {
      ENGINE_MIDI_MSG_NOTE_OFF         = 0x80,
      ENGINE_MIDI_MSG_NOTE_ON          = 0x90,
      ENGINE_MIDI_MSG_POLY_PRESSURE    = 0xA0,
      ENGINE_MIDI_MSG_CONTROL_CHANGE   = 0xB0,
      ENGINE_MIDI_MSG_PROGRAM_CHANGE   = 0xC0,
      ENGINE_MIDI_MSG_CHANNEL_PRESSURE = 0xD0,
      ENGINE_MIDI_MSG_PITCH_BEND       = 0xE0,
      ENGINE_MIDI_MSG_SYSEX            = 0xF0,
      ENGINE_MIDI_MSG_TIME_CODE        = 0xF1,
      ENGINE_MIDI_MSG_SONG_POSITION    = 0xF2,
      ENGINE_MIDI_MSG_SONG_SELECT      = 0xF3,
      ENGINE_MIDI_MSG_TUNE_REQUEST     = 0xF6,
      ENGINE_MIDI_MSG_TIMING_CLOCK     = 0xF8,
      ENGINE_MIDI_MSG_START            = 0xFA,
      ENGINE_MIDI_MSG_CONTINUE         = 0xFB,
      ENGINE_MIDI_MSG_STOP             = 0xFC,
      ENGINE_MIDI_MSG_ACTIVE_SENSING   = 0xFE,
      ENGINE_MIDI_MSG_SYSTEM_RESET     = 0xFF,
  } engine_midi_msg_type_t;

  typedef struct {
      uint32_t timestamp;
      uint8_t  type;
      uint8_t  channel;
      uint8_t  data1;
      uint8_t  data2;
      uint16_t value;
      uint8_t  sysex_len;
      uint8_t  sysex_data[ENGINE_MIDI_SYSEX_BUF_SIZE];
  } engine_midi_event_t;

  typedef struct {
      uint8_t vendor_id;
      uint8_t cmd_code;
      uint8_t func_code;
      uint8_t payload_len;
      uint8_t payload[ENGINE_MIDI_SYSEX_CMD_MAX_LEN];
  } engine_midi_sysex_cmd_t;
  ```
- **API**（C）：
  ```c
  esp_err_t engine_midi_init(void);
  esp_err_t engine_midi_feed_byte(uint8_t byte);
  esp_err_t engine_midi_feed_stream(const uint8_t *data, uint32_t len);
  ```

#### engine_sf2 — SF2 采样合成（上游移植）
- **职责**：波表合成算法，统一复音分配器
- **状态**：已移植 `SF2 引擎` 库，配置 `MAX_VOICES = 150`；所有发声调用（MIDI/App）都通过同一复音池获取 voice
- **输入**：MIDI 事件 / App 直接调用 `engine_sf2_note_on/off`
- **输出**：int16_t 立体声 PCM（通过 `service_audio` 路由）
- **说明**：当前唯一音频引擎，所有 App 共用同一复音池

### 9.3.1 关于音色文件

- **项目仓库不放任何 `.mid` / 采样文件**。
- 运行时从 SD 卡读取：
  - `/sdcard/soundfonts/*.sf2` → SF2 音色。
  - `/sdcard/midi/*.mid` → MIDI 播放器曲库。
- App 检测到文件不存在时给出友好提示。

### 9.3.2 多音与 MIDI 通道

- `SF2 引擎` 维护一个**统一的复音分配器**，不区分 MIDI/App/功能来源，所有发声调用都从同一个复音池获取 voice。
- 复音池上限为 **150 voice**；分配策略为：优先空闲槽，没有空闲则抢夺最老槽。
- App 触发合成器统一经 `engine_midi_publish()` 走 MIDI 总线，由 engine_sf2 内部分配 voice。
- 所有 Note On/Off 通过 `engine_midi_publish()` 或 `engine_sf2_note_on/off()` 进入同一复音池。

### 9.4 Services 层（直接使用 BSP）

Services **不创建硬件抽象**，直接使用 `espressif__m5stack_tab5` BSP API。

#### service_audio
- 封装 ES8388 I2S 音频输出

#### service_sd
- SDMMC + SPIFFS 挂载、文件枚举与 fopen 封装

#### service_page
- 系统屏幕 backend：boot/Launcher/setting/about/onboard 的 LVGL 控件事件处理与导航逻辑
- 依赖 `engine_gui`、`app_manager` 及各业务 service，为 UI 层提供统一入口

#### service_input
- UART MIDI 已实现；USB Host MIDI 由 `service_usb_host` 实现；BLE MIDI 为桩；当前单 USB PHY 硬件下，USB Device 初始化被跳过以避免 PHY 冲突

#### service_rtc
- RX8130CE RTC 驱动封装，提供时间读取/设置

#### service_power
- INA226 电池监测、IO 扩展器电源控制、USB-C/耳机检测；IO 扩展器输入读取采用互斥锁 + 缓存 + 重试，避免 I2C 竞争导致的 `pi4ioe5v6408: read_input_reg failed`；软件关机、待机唤醒

```c
static esp_err_t main_init_comm_and_appmgr(void)

    esp_err_t ret = engine_midi_init();
    if (ret != ESP_OK) {
        ESP_LOGE(TAG, "engine_midi_init failed: %d", ret);

    ret = app_manager_init();

{
    esp_err_t ret = service_sd_init();
    if (ret != ESP_OK) {
        ESP_LOGW(TAG, "service_sd_init failed: %s, fallback to SPIFFS resources", esp_err_to_name(ret));
    }
    main_boot_progress(32);
    main_yield();

    ret = engine_gui_init();
    if (ret != ESP_OK) {
        ESP_LOGE(TAG, "engine_gui_init failed: %d", ret);
        return ret;
    }
    main_boot_progress(20);

static esp_err_t main_init_network_and_peripherals(void)
{
    esp_err_t ret = service_rtc_init();

        ESP_LOGW(TAG, "service_rtc_init failed: %d", ret);
    }
    main_boot_progress(28);
    main_yield();

    if (!service_nvs_is_initialized()) {
        ESP_LOGI(TAG, "first boot, start config AP");
        ret = service_wifi_start_ap();

        }

        ret = service_wifi_init();
        if (ret != ESP_OK) {
            ESP_LOGW(TAG, "service_wifi_init failed: %d", ret);
        }

    ret = service_http_client_init();
    if (ret != ESP_OK) {
        ESP_LOGW(TAG, "service_http_client_init failed: %d", ret);

    task_network_start();
    main_boot_progress(45);
    main_yield();

    ret = service_input_init();
    if (ret != ESP_OK) {
        ESP_LOGW(TAG, "service_input_init failed: %s", esp_err_to_name(ret));
    }

    main_yield();

    return ESP_OK;

    service_audio_init();
    main_boot_progress(60);
    main_yield();

    /* 注册并激活唯一音频源 SF2 引擎*/
    engine_sf2_register_source();
    service_audio_activate_sf2();

    main_boot_progress(100);

    task_audio_start();

    return ESP_OK;
}

{
    esp_err_t ret = service_power_init();
    if (ret != ESP_OK) {
        ESP_LOGE(TAG, "service_power_init failed: %d", ret);
        return;
    }
    main_boot_progress(5);
    main_yield();

    if (main_init_comm_and_appmgr() != ESP_OK) return;

    ret = app_manager_register_all();
    if (ret != ESP_OK) {

        return;

    if (main_init_network_and_peripherals() != ESP_OK) return;
    if (main_init_audio() != ESP_OK) return;

    ESP_LOGI(TAG, "system boot complete, entering idle loop");

    while (1) {
        vTaskDelay(portMAX_DELAY);
    }
}
```

## 11. 5 点触摸支持

M5Stack Tab5 的 GT911/ST7123 触摸 IC 硬件支持最多 10 点同时触摸，但 ST7123 不提供 `track_id`；LVGL 的输入设备（`lv_indev_t`）原生按单点指针设计。当前项目在 `engine_gui` 中按 **5 点** 进行坐标帧间跟踪。

### 11.1 解决思路

将每个跟踪到的触摸点都注册为一个独立的 `lv_indev_t`：

```
触摸点 0  ──►  lv_indev_t *indev_0
触摸点 1  ──►  lv_indev_t *indev_1
   ...            ...
触摸点 4  ──►  lv_indev_t *indev_4
```

所有输入设备共享同一个 `esp_lcd_touch_handle_t`，在 `engine_gui` 中维护一个触摸数据缓存：

```c
static struct {
    uint32_t tick;
    uint8_t count;
    esp_lcd_touch_point_data_t points[CONFIG_ESP_LCD_TOUCH_MAX_POINTS];
} s_touch_cache;
```

缓存以 `xTaskGetTickCount()` 为键，同一个 tick 内只读取一次触摸 IC，避免多个 indev 各自发起 I2C 读取。

### 11.2 实现位置

- `components/engine_gui/engine_gui.c`
  - `engine_gui_init()`：移除 BSP 默认单点 indev，调用 `bsp_touch_new()` 创建独立触摸句柄，注册 `MULTI_TOUCH_MAX_POINTS` 个 `lv_indev_t`
  - `multi_touch_read_cb()`：按索引从缓存取坐标，返回 `PRESSED` 或 `RELEASED`
  - 触摸事件同时被打包为 `MIDI_CMD_INPUT` SysEx 发布到 `engine_midi`

### 11.3 依赖规则

- `engine_gui` 依赖 `espressif__esp_lcd_touch` 和 `espressif__esp_lvgl_port`
- 触摸 IC 由 BSP 初始化 I2C；`bsp_touch_new()` 复用同一 I2C 总线创建独立驱动实例

## 17. 版本控制约定

项目使用 Git 进行版本控制。AI Agent 在每次可构建的改动完成后，应主动执行 `git add -A && git commit` 固化变更， especially 对于 `components/engine_gui/` 下的 UI 工程文件、生成代码、字体与图片资源。

- **提交前必须构建通过**：`idf.py build` 零错误（`ESP_ROM_ELF_DIR` 等可忽略警告除外）。
- **提交信息使用中文**：简洁描述变更点与验证结果，例如 `feat(gui): 完成开机页布局`。
- **全量暂存**：使用 `git add -A`，不手动挑选文件。
- **不主动推送**：`git push` 仅在用户明确要求时执行。
- **禁止危险操作**：未经用户确认，禁止 `git reset`、`git rebase`、`git checkout -f`、`git clean -fd`。

## 18. 骨架生成脚本

`tools/gen_arch.py` 用于生成/更新模块骨架，支持参数化：

```bash
python tools/gen_arch.py --list                  # 列出所有模块
python tools/gen_arch.py --module engine_midi    # 生成单个模块
python tools/gen_arch.py --category engine       # 批量生成分类
python tools/gen_arch.py --all --force           # 全量生成（覆盖所有文件）
python tools/gen_arch.py --dry-run --all         # 预览全量生成
```

**注意**：`--module` / `--category` 只生成指定模块，不会覆盖其他手写代码；`--all --force` 会覆盖所有模块及 `main.c` / `CMakeLists.txt`。
